# Référentiel documentaire — Purpose Capital S.A.

Lire `README.md` avant toute modification : arborescence, génération, versionnage (`tools/version.mjs`), visas électroniques, publication.

- Site publié (artefact claude.ai, privé) : https://claude.ai/artifact/LmKmic7atsYRxmhaARpNWv — republier avec `root=dist`, sans repasser `capabilities` (les règles d'accès de la base des visas sont déjà déclarées).
- `npm install` puis `node build.mjs` (site + PDF + Word) ou `node build.mjs --no-pdf`. Chromium : `PLAYWRIGHT_BROWSERS_PATH` si nécessaire.
- Rédaction : ton clair et compréhensible de tous ; bonnes pratiques occidentales adaptées au Cameroun et à la CEMAC, appuyées sur les textes CEMAC/COSUMAF ; rôles désignés par leur titre, jamais par un nom ; structure « ## Titre X — … » / « ### Article N — … ».
- YAML : toute valeur contenant « : » entre guillemets (sinon un élément de liste devient un objet).
- Ne jamais écrire de visa dans la base à la place d'une personne. Les visas se lisent (ArtifactData, collections `roles` et `sig`) puis `node tools/version.mjs visas <export>`.
- Le Guichet (dépôt totostar1900/guichet) reprend la convention de compte-titres (articles 1 à 10) : toute modification de l'un se reporte dans l'autre le même jour.
- Site hébergé : https://referentiel.purposecapital.africa — application `app/` (Next.js, projet Vercel « procedure » (équipe purpose-capital), racine `app`), connexion Microsoft 365, base Supabase « Referentiel » (qrmoozapvnfmbtibofup : tables `membres`, `kv`, `journal`, RLS). Le shim `app/shim/shim.js` émule `window.claude.use(...)` : la page reste identique à l'artefact. `dist/` est versionné ; l'Action « Publier le référentiel » le régénère à chaque modification des sources.
- Circuits et rédaction en ligne (site hébergé) : base `kv` — `circuits/<type>` (admin), `figes/<id>~<empreinte>` (circuit figé au premier visa), `etats/<id>` (abrogé : admin ou RCCI ; supprimé : admin), `redaction/<id>` (brouillons : fonction `redac` ou admin), `auteurs/<id>~<empreinte>` (écrit par la publication automatique ; les rédacteurs ne visent pas leur version). Les brouillons soumis sont appliqués par `.github/workflows/appliquer.yml` (`tools/appliquer.mjs`, secret GitHub `SUPABASE_SERVICE_ROLE_KEY`), déclenché par `/api/appliquer` (variable Vercel `GITHUB_DISPATCH_TOKEN`) ou chaque heure.
- Adoption automatique : quand la dernière étape d'un circuit est visée, la page dépose `adoptions/<id>~<empreinte>` (statut « demande ») et déclenche la publication ; `tools/adopter-auto.mjs` revérifie les visas dans la base, passe le document en vigueur (v1.0 pour un premier projet), archive l'ancienne version, complète `content/approbations.json` (fiche de maîtrise des PDF). L'empreinte ne change pas.
- Accès employé (`membres.acces = 'employe'`) : la page et les fichiers ne contiennent que les documents attribués (`lectures/<doc>.ids` ou `.consult`), filtrés par `app/app/route.ts` et `app/app/fichier/…` ; la base limite aussi ce qu'il lit (kv, annuaire réduit aux approbateurs).
